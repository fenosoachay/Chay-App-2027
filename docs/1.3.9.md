# 1.3.9 : sous-playlists, notification « Nouvelle version », ordre du multimédia

## 1. Sélecteur de sous-playlist vide

**Cause exacte** : en prod, le champ `Playlist.parent_id` existe (`migrer-playlists.mjs` répond « déjà à jour »), mais il porte l'option **« Hidden »**. PocketBase n'accepte alors ce champ que du superuser. Pour un admin de l'app :

- il le **retire de la requête, sans erreur**, avant même les hooks : la création répond 200, mais `parent_id` reste vide en base ;
- il ne le renvoie pas non plus dans les réponses.

La « sous-playlist » devient donc une playlist de premier niveau, et le sélecteur de classement, qui ne liste que les sous-playlists, reste vide dans toutes les sections.

L'app envoie pourtant bien `parent_id` : vérifié en bac à sable, en base, par l'écran admin sur ordinateur et sur téléphone. Sur une copie du bac à sable où ce champ est passé en « Hidden », le symptôme de la prod est reproduit à l'identique.

**Diagnostic de la prod (lecture seule)**, par le tunnel, avec le superuser saisi masqué :

```powershell
node pocketbase/scripts/diagnostiquer-playlists.mjs
```

Il doit afficher `Champ parent_id : présent, CACHÉ (option « Hidden »)`.

**Correctifs** :

- **`migrer-1-3-9.mjs`** retire l'option « Hidden » de `parent_id` et de `category`. `migrer-playlists.mjs` fait de même, et ne répond donc plus « déjà à jour » à tort.
- **Hook `playlists.pb.js`** :
  - tant que le champ est caché, toute écriture de playlist par un admin de l'app est refusée avec un message explicite, au lieu de corrompre les données en silence ;
  - un champ absent est refusé de la même façon ;
  - la parente doit être de premier niveau et appartenir à la même section.
- **Fenêtre de création** : elle relit la playlist enregistrée et annule si le rattachement a été perdu.
- **Panneau admin** : un bandeau s'affiche si le champ est caché ou absent.

**Réparation des sous-playlists créées à tort**, après `migrer-1-3-9.mjs --appliquer`, avec le superuser :

```powershell
node pocketbase/scripts/reparer-sous-playlists.mjs --modele C:\Temp\rattachements.json
node pocketbase/scripts/reparer-sous-playlists.mjs --fichier C:\Temp\rattachements.json
node pocketbase/scripts/reparer-sous-playlists.mjs --fichier C:\Temp\rattachements.json --appliquer
```

1. **Lister** (lecture seule) : le script écrit la liste des playlists de premier niveau sans sous-playlist, par section.
2. **Compléter** le fichier :
   - écrire le nom de la parente dans `"parente"` ;
   - supprimer les lignes des vraies playlists de premier niveau ;
   - si deux playlists portent le même nom dans une section, utiliser `"sous_id"` / `"parente_id"`.
3. **Simuler**, puis **appliquer**. Le script refuse :
   - une autre section ;
   - une parente qui est elle-même une sous-playlist ;
   - une playlist qui a déjà des sous-playlists ;
   - un nom ambigu.

La sous-playlist est placée à la fin de celles de sa parente, et les contenus qui y sont déjà liés restent liés. Le script peut être relancé.

**Autre solution** : supprimer ces playlists et les recréer dans l'app avec le bouton dossier « Nouvelle sous-playlist », après la migration.

## 2. Notification « Nouvelle version » → « À propos »

Deux défauts corrigés :

- **App fermée** : « À propos » était ouvert dans l'accueil. Or `AnimatedOutlet` remonte la page dès que l'adresse change (sa clé combine chemin et paramètres). Le retrait du paramètre `?apropos` refermait donc la fenêtre avant qu'elle soit vue. Elle est maintenant ouverte par `Layout`, au-dessus des pages.
- **Push navigateur renvoyé par la file de reprise** : ces envois ne gardent pas la route. Le service worker ne connaissait pas `app_update` et ouvrait l'accueil.

Vérifié dans le navigateur : avant le correctif, l'arrivée directe laissait « À propos » fermé ; après, la fenêtre s'ouvre, que l'app soit fermée ou déjà ouverte.

## 3. Ordre du multimédia (admin, cadenas, vu par les membres)

Un même cadenas (admin seulement) et le même glisser qu'en YouTube (`ListeTriable`) partout :

| Liste | Enregistrement |
|---|---|
| Sections de la grille Multimédia | `MediaOrder` (clé `sections`) |
| YouTube : Culte, Louange, Célébration | `MediaOrder` (`youtube:<section>`) |
| Galerie : Église, Mindset, Non classées | `MediaOrder` (`galerie:<section>`) |
| Playlists et sous-playlists de YouTube, Articles, Galerie | `Playlist.order` (existant) |
| Actualité chrétienne, Fonds d'écran | champ `order` (existant) |
| Musique, Prédication, Articles, contenus des sous-playlists | déjà en place, inchangé |

**YouTube** : avant, la gestion admin enregistrait l'ordre dans les **préférences personnelles** de l'admin, que les membres ne voyaient jamais. L'ordre est maintenant partagé ; un membre peut toujours réorganiser pour lui-même par-dessus.

**Contenus ajoutés après un réordonnancement** : ils apparaissent en tête (les nouvelles sections, en fin de grille).

**Films** : non touché.

**Migration `migrer-1-3-9.mjs`** (non exécutée) : elle crée la collection `MediaOrder` avec :
- les champs `key` (unique) et `ids` (json) ;
- la lecture pour les membres connectés, l'écriture pour les admins.

Fragment pour `collections.json` : `pocketbase/config/collections-1-3-9.json`. Avant cette migration, l'app affiche l'ordre d'avant, et l'admin reçoit un message clair s'il tente de réordonner.

## Ordre de déploiement

1. **Diagnostic des playlists** (lecture seule).
2. **Migration du schéma** (option « Hidden » retirée de `parent_id`, collection `MediaOrder`) :

   ```powershell
   node pocketbase/scripts/migrer-1-3-9.mjs
   node pocketbase/scripts/migrer-1-3-9.mjs --appliquer
   ```

   La simulation annonce `Playlist.parent_id : option « Hidden » retirée…` et `MediaOrder : nouvelle collection`. Relancée, elle répond « Déjà à jour ».
   Ensuite : **réparation** des sous-playlists créées à tort (`reparer-sous-playlists.mjs`, voir plus haut).
3. **Fichiers serveur** : `pb_hooks/playlists.pb.js` (nouveau), puis redémarrer PocketBase. Le journal annonce toujours **6 tâches planifiées**.
4. **Site** : il contient le service worker corrigé (`public/sw.js`). Le navigateur le met à jour à la visite suivante.
5. **APK 1.3.9** (aucun changement natif), puis l'annonce de version.

Réglages : aucun. Caddy, R2 et les variables d'environnement sont inchangés.
